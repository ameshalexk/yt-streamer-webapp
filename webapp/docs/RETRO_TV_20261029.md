# Retro TV — isolated page (2026-10-29)

**Status:** development branch / draft PR only. **Do not merge or deploy without separate approval.**
Primary YT Streamer playback and production routing remain unchanged by this feature while `RETRO_TV_ENABLED` is unset.

## User requirements

- Separate URL from the normal player: `/retro-tv/`, with optional dedicated hostname `retro.ameshalex.com` when its DNS/Cloudflare Access ingress is explicitly configured.
- **Only** existing WebCodecs (H.264 + its current audio decoder) and buffered MJPEG (JPEG frames + existing separate MP3 audio) playback.
- No native video, HLS, MPEG-TS or JPEG XL playback in the Retro TV page.
- No production deployment or DNS change now.

## Source and independent branding

Spelunkr's public About page confirms it plays media from Internet Archive, but it does not document an open schedule API. Its guide/schedule are original site content. This feature **does not claim to reproduce Spelunkr's exact 29 channels** and does not scrape its guide.

The initial documented feed is `https://www.orphanedfilms.com/api/tv` from the open project at
`https://github.com/amponce/archive-movie-browser`. Its JSON includes `channels[].now.film.url`, `channels[].now.offset`, `startsAt`, `endsAt`, and upcoming programs. It publishes channels with the source's own scheduling; the UI acknowledges the source.

The server adapter validates each media URL as HTTPS `archive.org/download/...`, filters unsafe/malformed entries, caches 45 seconds, and enforces an 8 MiB maximum response. Film links and guides may disappear or be blocked by the upstream host; **Internet availability and real playback have not been verified**.

## Playback

1. UI obtains the sanitized guide from `/api/retro-tv/channels`.
2. On tune, UI derives the current film offset using the feed's timestamp.
3. **WebCodecs:** the current `/api/experimental/cyberdash/start` endpoint accepts Archive.org URLs only while the Retro TV feature flag is enabled. It passes a single video-with-audio source to the existing FFmpeg/DASH/WebCodecs pipeline, with the computed `startAt`.
4. **MJPEG:** the current `/stream/url` serves buffered JPEG frames; `/stream/audio/url` now uses the same `timestamp` offset for its separate MP3 sidecar.
5. On WebCodecs failure, the page switches to buffered MJPEG. Stopping or changing channels cleans up player sessions. A timer refreshes the guide to switch on programme turnover.

The existing source video, server FFmpeg binaries, audio settings and original WebCodecs code are not changed. Archive playback shares existing stream concurrency caps.

## Route and release safety

- Default `RETRO_TV_ENABLED` is **off**. When off, `/retro-tv/*` and the guide return 404 and Archive URLs are not enabled in the WebCodecs resolver.
- Local development: `RETRO_TV_ENABLED=1 npm start`, then open `http://127.0.0.1:8099/retro-tv/`. Keep this on an isolated environment, not production.
- Optional hostname: `RETRO_TV_HOST=retro.ameshalex.com` restricts requests on that host to Retro TV assets, guide, WebCodecs endpoints and MJPEG endpoints, and redirects `/` to `/retro-tv/`. **Do not configure public DNS/Tunnel or Cloudflare Access until a deployment is authorized**. Use the existing protected origin. TLS and Access are not established by this code.
- There are no changes to production launchd, HA add-on configuration, Cloudflare tunnels, DNS, TeslaMon, or existing playlist libraries.
